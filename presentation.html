Problem Space

The Setup & The Constraint

What are Decentralized Exchanges (DEXes)?

On-chain smart contracts that hold two token reserves (x, y) and price every swap deterministically by a formula — no order book, no counterparty. State is public and event-driven.

Price of the same token pair diverges across DEXes due to independent reserve state. The gap is the opportunity.

The Atomicity Guarantee

A blockchain transaction is fully atomic: if any step fails, all state changes revert. We encode a profit check inside the on-chain contract — if the net output doesn't exceed our floor, the entire tx reverts. No partial losses.

The Timing Constraint

A new block is produced every 2 seconds on our target chains. Each block is final — the price gap either exists in this block or it doesn't.

  • Competing bots also subscribe to the same events
  • Block sequencer orders by priority fee — first submitted, first included
  • Detection + submission must complete in <50ms to be competitive
  • Original JavaScript engine: 600ms per evaluation cycle — 12× too slow

Trade Shapes

  • 2-hop: A → B on DEX 1, B → A on DEX 2. Net profit if spread > gas cost.
  • Triangular: A → B → C → A across three DEXes. Loop closes richer.

PoolInfo Schema

struct PoolInfo {
  reserve0:   U256,       // token A balance
  reserve1:   U256,       // token B balance
  decimals0:  u8,         // normalisation
  decimals1:  u8,
  is_stable:  bool,       // curve selector

}

Cache key encodes exchange + token pair + fee tier. Built once at startup — no format!() in the hot path.

Freshness Guards

Stale state is worse than no state — it produces phantom opportunities.

  • Volatile pools: expire after 60s of silence
  • Stable pools: expire after 120s (slower price drift)
  • Returns None when stale — never quoted

Tradeoff: a pool with no activity for 60s genuinely has no spread — safe to skip.

Algorithms

AMM Pricing: Two Invariant Curves

Curve 1 — Volatile pools: xy = k

Constant product. Used by: Uniswap V2, Aerodrome volatile, SyncSwap classic.

// Closed form: O(1)
dy = y · dx / (x + dx)

// After fee deduction:
dx_adj = dx · (10000 - fee_bps) / 10000
dy     = y · dx_adj / (x + dx_adj)

Reserves normalized to 18 decimals before calculation, then scaled back. Exact integer arithmetic — no floats.

V3 — Concentrated Liquidity (different model)

Liquidity is distributed across discrete price "ticks." Local xy=k approximation breaks at tick boundaries. A large trade may cross a tick and get a significantly worse price than the spot formula predicts. This causes phantom profits — covered in Challenge 1.

Curve 2 — Stable pools: x³y + xy³ = k

Designed for pegged assets (e.g. USDC/USDT). Keeps prices near-equal at low-to-mid volumes. No closed-form inverse — requires iterative solver.

// Newton-Raphson: find y given x, dx, k
f(y)  = x³y + xy³ − k
f'(y) = x³ + 3xy²

loop {
    dy = f(y_n) / f'(y_n)
    y_{n+1} = y_n − dy
    // stop when correction negligible
    if dy ≤ 1_wei { break }    // ← key fix
}

// Typical convergence: 5–8 iterations
// Previous impl: fixed 255 iterations
// Optimization: ~240 wasted iters/call saved

The dy ≤ 1 wei convergence fix replaced a dy == 0 check that in normalized 10¹⁸ space almost never triggered on time.

Scan Pipeline

Opportunity Detection Loop

2-Hop Detection

1

Event received → update pool_cache for affected pool

2

For each (tokenA, tokenB) pair × each router pair: look up both pools in cache

3

Apply AMM formula: amountOut = f(reserveA, reserveB, amountIn)

4

Check: amountOut − amountIn > gas_cost_usd + min_profit_usd

5

(gated) If V3 and tick-cap suspected: run QuoterV2 eth_call to get real amountOut

6

Pre-flight simulation: eth_call(tx) — if reverts, discard with zero gas cost

7

Sign + broadcast eth_sendRawTransaction

Triangular (3-Hop) Detection

// Phase 1: A → B across all routers
p1_entries = [
  { amountB = quote(A→B, routerX), router },
  ...
]

// Phase 2: B → C for each p1 result
p2_entries = [
  { amountC = quote(B→C, routerY), ... },
  ...
]

// Phase 3: C → A to close the loop
p3_entries = [
  { amountA' = quote(C→A, routerZ), ... },
  ...
]

// Profit: amountA' − amountA − gas_cost
if profit > floor { emit opportunity }

All three phases use local pool_cache. Zero network calls. Complexity: O(pairs × routers³) but bounded by config.

Complexity in Practice

  • ~13 active pairs per chain
  • 4–6 router combinations per pair
  • Total candidates per event: ~50–80
  • All evaluated in <1ms (pure arithmetic)
Module — Smart Contract

On-Chain Safety Layer (Solidity)

Execution Flow (simplified)

function executeArbitrage(
  tokenIn, tokenOut,
  amountIn, minProfit,
  deadline, routerA, routerB, ...
) external nonReentrant {

  // 1. Time guard
  require(block.timestamp <= deadline)

  // 2. Snapshot starting balance
  uint256 before = tokenIn.balanceOf(this)

  // 3. Execute both legs atomically
  _executeSwap(routerA, tokenIn→tokenOut, amtIn)
  _executeSwap(routerB, tokenOut→tokenIn, amtOut)

  // 4. Profit gate — reverts entire tx if not met
  require(tokenIn.balanceOf(this) - before >= minProfit)
}

5 Exchange Protocol Dispatch

Each DEX type has a different swap interface. The contract dispatches based on a RouterType enum set at whitelist time:

  • V2 — swapExactTokensForTokens()
  • V3 — exactInputSingle() (7-field SwapRouter02)
  • Solidly — swapExactTokensForTokens(routes[])
  • Aerodrome — Solidly + extra factory field in route
  • SyncSwap — direct transfer to pool, then pool.swap()

Security Properties

  • ReentrancyGuard — nonReentrant modifier; blocks re-entry via malicious token callbacks
  • Ownable2Step — two-transaction ownership transfer; typos don't lock the contract
  • Pausable — emergency halt without fund movement
  • Router whitelist — only pre-approved exchange addresses can be called
  • Approval hygiene — exact approve(amount) before each leg, reset to 0 after
  • Deadline — stale pending txs expire; no replaying into changed market state

Challenge 1

Phantom Profits: Local Math vs Reality

Root Cause

V3 Concentrated Liquidity Tick Boundary

Uniswap V3 distributes liquidity in discrete price "tick" ranges. Our xy=k spot formula treats liquidity as continuous — correct within a tick, wrong across a boundary.

Observed: V3 pool shows 4.9% spread → $0.32 profit on $100 trade.
Reality: trade crosses tick boundary, capped at $65. Real profit: $0.003.

Detection signal: if local_amountOut < configured_trade_size, the tick cap truncated the quote. The local formula is unreliable.

Other Phantom Sources
  • Non-existent pool echo — some routers return amountIn == amountOut for unknown pairs (0% gain disguised as a spread)
  • Stale sqrtPriceX96 — V3 spot price moved after our last event but before scan completes
  • 3-leg compounding — small overestimate at each leg multiplies into a large phantom gain
Fix: Two-Phase Verification (Phase 1.5)
// Phase 1: local AMM spot quote (0 I/O)
let spot = pool_cache.get_amount_out(key, amt)

// Tick-cap heuristic
if spot < configured_trade_amount {
    // Local quote is truncated — fire ONE
    // batched QuoterV2 multicall at full size
    let real = QuoterV2
      .quoteExactInputSingle(full_amt)
      .await?
    // Update candidate in-place
    candidate.amount_in = real
}

// Sanity cap: >5% spread = phantom
if profit_pct > 0.05 { discard() }

QuoterV2 is an on-chain read-only contract that simulates the exact execution path including all tick crossings. One multicall covers all V3 candidates per scan.

Result

V3 revert rate dropped significantly. The 4.9% phantom now correctly resolves to $0.003 → below floor → discarded.

Challenge 2

Silent Data Staleness: Event Schema Mismatch

The Bug

Same event name, different ABI type → different topic hash

// Uniswap V2 family:
event Sync(uint112 reserve0, uint112 reserve1)
keccak256("Sync(uint112,uint112)")
→ 0x1c411e9a96e071241c2f21f7726b17ae...

// Aerodrome / Solidly family:
event Sync(uint256 reserve0, uint256 reserve1)
keccak256("Sync(uint256,uint256)")
→ 0xcf2aa50876cdfbb541206f89af0ee48b...

// Listener filtered on V2 hash only ↑
// Aerodrome events arrived and were DISCARDED
Failure Mode

Aerodrome is the highest-volume exchange on Base. Its price events streamed in correctly — but the listener discarded every one as an unknown event signature.

After 60 seconds: VOLATILE_MAX_AGE expires → every Aerodrome quote returns None. We were completely blind to the primary source of opportunities on our main chain, with no visible error.

Fix
// Compute both fingerprints at startup
let v2_sync      = keccak256(b"Sync(uint112,uint112)")
let solidly_sync = keccak256(b"Sync(uint256,uint256)")

// Subscribe to BOTH topics in the WS filter
event_sigs.push(v2_sync)
event_sigs.push(solidly_sync)

// Decode raw bytes based on matched topic
match log.topic0 {
  t if t == v2_sync => {
    let r0 = U256::from_be_slice(&data[0..16])
    let r1 = U256::from_be_slice(&data[16..32])
    pool_cache.update(addr, r0, r1)
  }
  t if t == solidly_sync => {
    let r0 = U256::from_be_slice(&data[0..32])
    let r1 = U256::from_be_slice(&data[32..64])
    pool_cache.update(addr, r0, r1)
  }
}
Result

Aerodrome pools stay live on every swap. Went from 0 Aerodrome hits to the majority of detected opportunities on Base.

Lesson: in a binary protocol, event names are irrelevant. Identity is the keccak256 of the full ABI signature including parameter types.

Challenge 3

Block Queue Racing: FCFS Sequencer

The Problem

Base: Priority Fee Ordered Transaction Queue

Base's sequencer processes each block's transactions strictly by gas tip (priority fee). A bot submitting at block confirmation arrives after bots that submitted at event time — 200ms earlier.

  • We were consistently landing at position 500+ per block
  • Opportunity already taken by position 10–20
  • Adding a QuoterV2 verification step: +80–160ms — made it worse

Lever 1: Tip Escalation

Raised priority fee: 1 Mwei → 25 → 200 Mwei. Higher tip moves up the queue. But other bots escalate too — cost war is not sustainable alone.

Lever 2: Optimistic Submission

Skip QuoterV2 on Base. Submit after Phase 1 spot quote. Accept higher revert rate in exchange for 80–160ms earlier arrival. Gas cost of failures is accounted in profit floor.

Key Strategy: Pending TX Mempool Monitor

Instead of waiting for block confirmation, subscribe to eth_subscribe("newPendingTransactions") — the unconfirmed transaction queue.

1

Large swap appears in mempool (e.g. $50k USDC→ETH on Uniswap)

2

Decode calldata: identify token pair, amount, exchange

3

Simulate post-swap state: apply AMM formula to get new reserves

4

Check if our arb is profitable given those new reserves

5

Submit our tx with the same tip → sequencer places us in the same block

The large pending swap creates the price gap — we race it into the same block and close it atomically after it executes.

Parses Uniswap UniversalRouter (0x3593564c) calldata format — covers the majority of Base swap volume.

Performance Engineering

Micro-Optimizations: Where They Actually Mattered

Dead Code Elimination (~150 lines)

Triangular scanner had multicall infrastructure that ran empty every scan:

// Was: 3× per scan, always no-ops
let p1_mc: Vec<(Address, Bytes)> = Vec::new()
let p2_mc: Vec<(Address, Bytes)> = Vec::new()
// ...never pushed to...
run_multicall(provider, p1_mc).await  // ← empty

// Fix: removed all multicall infrastructure
// Triangular is purely local — always was

Found via code audit: let mc_call: Option<...> = None was hardcoded — the push branches never executed.

Allocation Hotspots Removed

  • String dedup — dedup_by_key(|o| format!("{}|{}", ...)) → dedup_by(field compare): eliminates one String allocation per candidate
  • Case conversion — symbol.to_uppercase() in token_amount_to_usd → removed. Symbols are always uppercase in config. Was 100–500 allocs/scan.
  • RouterType Copy — unit enum, 9 .clone() calls in hot path → Copy trait, zero-cost
  • Opportunity summary string — replaced multi-string concat with single with_capacity write

Structural Wins

  • Pair-targeted scanning — pre-built HashMap<Address, Vec<PairIdx>> at startup. On event: look up affected pairs only. Was O(all pairs) → O(affected pairs) per event.
  • Block-level gas price — baseFee arrives with every newBlock event. Eliminated periodic eth_gasPrice RPC call.
  • SharedState read-once — dry_run flag pre-read once before the candidate loop, not per candidate.
  • Signing outside lock — secp256k1 signing (~10ms) moved outside the executor Mutex. Lock now covers only nonce fetch + TX build.
  • Channel buffer — swap event channel: 256 → 1024 slots. Absorbs bursts without dropping events on congested blocks.

Key Decisions & Numbers

Architectural Decisions

  • Event sourcing over polling — eliminates all I/O from the hot path. Tradeoff: staleness window, mitigated by freshness guards.
  • Rust over Go/Python — compile-time concurrency safety caught real race conditions. Zero-cost abstractions mean no perf/safety tradeoff.
  • Optimistic submission on FCFS chains — skip verification, accept higher revert rate, gain 80–160ms queue advantage.
  • Pending mempool monitor — race to the same block as the price-moving trade, not the next one.
  • Pre-flight eth_call simulation — dry-run every candidate against the node before spending gas. Catches stale-state reverts at near-zero cost.
  • Two-phase V3 verification — local spot for speed; QuoterV2 gated fallback for accuracy when tick-cap is detected.

Lessons Learned

  • In binary protocols, event identity is the full ABI signature hash — names are cosmetic
  • Local math breaks at model boundaries (V3 tick caps); two-phase verification is the pattern
  • On priority-fee chains, the mempool is the competitive layer, not the block
  • The most impactful optimization was removing I/O, not shaving CPU cycles
  • Dead code that looks active (it allocates, it awaits) is harder to find than truly dead code
